# P2 Roster V2 — derive, don't inherit

Workstream: agent roster derivation. Date: 2026-09-30. No API spend; all
measurements local (installed bundles, repo files, ECC clone), plus web
accounts cited inline. Companion: `2026-09-30-P2-ecc-mining.md` (W2 —
inventory and ports). This doc audits W2 §6 as a claim, not a conclusion.

## 1. Demand-side evidence

### 1a. What the vendors ship as built-ins — PROVEN (bundle + official docs)

Copilot CLI 1.0.89 (`~/.cache/copilot/pkg/linux-x64/1.0.89/definitions/`):
7 named agents + 1 background agent + 4 sidekicks.

| Agent | Model tier | Surface | Differentiator |
|---|---|---|---|
| explore | cheap (luna/mini), low effort | read-only + read-only MCP | context isolation, parallel-safe |
| task | cheap (luna/mini/haiku) | all, shell-led | output contract: summary on success, full output on failure |
| code-review | inherit | all tools, edits forbidden by prompt | read-only contract, high-confidence-only findings |
| security-review | inherit | all tools, prompt-scoped | checklist (11 vuln categories), >80% confidence gate |
| research | strong (Sonnet) | all | autonomy contract, citation-bearing output |
| rubber-duck | dynamic | all, no edits | adversarial stance (critic) |
| rem-agent | inherit | ONE tool (context_board) | memory consolidation, background |
| sidekicks ×4 | cheap (haiku/mini) | 1–3 tools each | background context retrieval, inbox-only output |

Claude Code (official sub-agents docs): Explore (Haiku, read-only),
Plan (inherit, read-only), general-purpose (inherit, all tools), plus
helper agents (statusline-setup, claude-code-guide).

**Finding:** across 17 vendor built-ins, zero are domain personas. There is
no built-in backend, frontend, or data agent anywhere. Every built-in is a
*workflow function* — explore, plan, run, review, secure, research, remember.
Both vendors independently converged on the same six functions. PROVEN by
inspection of the installed bundle and Anthropic's docs.

### 1b. What the ecosystem ships — ECC composition (PROVEN as supply)

ECC (affaan-m/ECC, local clone): 68 agents, 293 skills — a 4.3:1
skill-to-agent ratio. Agent mass by category:

- 23 reviewers, of which 17 are per-language/per-framework
  (python-, typescript-, go-, rust-, django-, react-, …)
- 11 build-resolvers, 10 of them per-language
- 34 workflow/other, incl. niches with near-zero general demand
  (homelab-architect, healthcare-reviewer, gan-* trio, seo-specialist)

**Finding:** ecosystem supply is stack-shaped, not org-chart-shaped. The
recurring units are triggered by concrete events (build is red, PR is open)
and scoped to a stack. Nobody ships "backend" as the unit; they ship
"python-reviewer." Inclusion in ECC is supply, not usage — per-agent usage
rates are **UNVERIFIABLE** (no telemetry exists).

### 1c. What practitioners report using — observed, small-n, firsthand only

- dev.to (practicing dev, firsthand): tried startup-persona agents; the
  combination that survived was **engineer + reviewer**. Mechanism named:
  the reviewer starts with fresh context and catches the author's drift
  early. Personas beyond the pair were dropped.
- Medium (Flutter dev, firsthand): UI / logic / backend / test split —
  but the split follows *module boundaries in one codebase* (parallel
  partitions of work), not job titles. The value claimed is parallelism,
  not expertise.
- Multiple practitioner guides converge on **model-tier routing** as the
  main lever actually used (Haiku for review/explore, mid-tier default,
  top-tier for architecture) — i.e. the axis practitioners exploit is the
  model, not the persona.
- No firsthand account found of anyone productively running more than ~6
  custom agents; accounts converge on 2–4. Listicles claiming 15+ agent
  rosters are template dumps, not usage reports. "More agents = better"
  is **REFUTED** as a description of practice; as a general law it stays
  UNVERIFIABLE.

## 2. Supply-side reality — the four axes and the rent

An agent earns its slot only if it differs from the base agent on at least
one axis that changes outcomes:

1. **Tool surface** — restriction (read-only reviewer cannot "fix" what it
   judges) or extension (a tool the base lacks).
2. **Model tier** — cheap/fast for search and command-running; the saving
   is real and per-invocation.
3. **Context contract** — isolation (search noise, test output stay out of
   the main window) and output shape (summary-on-success, findings-only).
4. **Stance** — adversarial/independent (critic, evaluator) where sharing
   the author's context is itself the failure mode.

A persona prompt with the same tools, same model, same context differs on
zero axes. It is a hat.

Rent, measured on this repo (description = the always-loaded delegation
surface; body loads only on invocation):

| Set | Desc chars | ≈ tokens, every session |
|---|---|---|
| V1 three (backend, data-scientist, ux-ui) | 381 | ~95 |
| Current canonical 12 (3 + 9 ECC ports) | 2,186 | ~546 |
| All 68 ECC agents, if installed wholesale | 14,169 | ~3,542 |

For scale: this project's own S10 decomposition put Copilot's entire
default surface at 14,510 input tokens. Wholesale ECC agents would add
~24% on top of that in descriptions alone, before a single invocation —
for a catalog in which (per §1c) most entries would never fire. Bodies are
the second rent: the ported code-reviewer body is 13,246 chars, paid per
invocation; fine if it fires daily, waste if it fires never.

## 3. Audit of the inherited three — PROVEN by frontmatter diff

| Agent | model_hint | tools_hint | Axes differentiated |
|---|---|---|---|
| backend | strong-reasoning | read, edit, shell, search | none |
| data-scientist | strong-reasoning | read, edit, shell, search | none |
| ux-ui | strong-reasoning | read, edit, shell | none |

Identical model, near-identical tools. The bodies are scope statements —
knowledge, not mechanism. As agents: three hats on the base agent.

Per-agent disposition:

- **backend — does not survive as an agent.** API contracts, idempotency,
  migration discipline are knowledge; they belong in a skill the base agent
  loads on server-side work. (Disagrees with W2 §6, which keeps it as a
  default on "matches daily use" — that is the inheritance logic again:
  frequency of the *topic* is not differentiation of the *agent*.)
- **data-scientist — the function survives, the form does not.** Its real
  content is a protocol (pre-register, baseline, effect size) plus one
  genuine axis W2 didn't score: separation of duties. An evaluator that
  can edit will eventually fix what it measures. Reborn as `evaluator`:
  read + shell, **no edit**, stance axis + tool axis. In this workspace —
  where the work product is evals — that's a daily tool. As a generic
  developer default, W2 is right that measurement is episodic.
- **ux-ui — does not survive today.** Its claimed job (verify rendered
  output) is unimplemented: its surface has no browser tool, so it cannot
  do the one thing that would differentiate it. Demote to a skill
  (design-system fidelity, a11y checklist). Resurrection condition:
  wire the Playwright MCP (already ported as optional by W2) into a
  screenshot-verify loop; until that loop exists, agent form is
  UNVERIFIABLE.

Audit of W2's other default picks, same test:

- **tdd-guide (agent) + tdd-workflow (skill)** — same content in two
  forms. The skill carries the procedure; the agent adds only rent.
  Keep the skill, kill the agent.
- **planner** — duplicates Claude Code's built-in Plan on one tool, fills
  a real gap on the other (Copilot ships no plan agent). Provisional;
  the A/B in §4 is Copilot-side only.
- **code-explorer** — both vendors already ship this function (§1a).
  Shipping ours is justified only by a measured delta (output contract,
  no GitHub-MCP weight). Provisional; A/B against each built-in.
- **code-reviewer, security-reviewer, build-error-resolver** — survive
  the axes test (see §4). W2's picks stand.
- **doc-updater** — overlaps this workspace's wiki-lint/session-harden.
  REFUTED by redundancy; drop.
- **Missing from W2:** a task/command runner — the vendor pattern with
  the clearest mechanism (Copilot `task`) and no ECC equivalent ported.

## 4. Roster V2 — ranked for Samuel (full-stack, AI team, demo today)

Ranking = expected value in his work, not generic value. Each entry:
(a) job, (b) why not base + prompt, (c) distinct surface, (d) the A/B
that proves or kills it.

**1. explorer** (new; mirrors both vendors' built-in)
(a) Codebase Q&A and search on unfamiliar repos.
(b) Base agent searching inline pays the search noise in main context
and at main-model prices; the saving is mechanical, not promptable.
(c) Read-only tools, cheap model tier, parallel-safe, short cited answers.
(d) 10 questions on an unfamiliar repo: main-context tokens to correct
answer + accuracy vs base inline. Kill if the delta is <20% context or
accuracy drops.

**2. code-reviewer** (ECC port, keep)
(a) Post-change review gate.
(b) The author reviewing its own diff in its own context is the failure
mode practitioners independently name (§1c). Fresh context + a no-edit
rule are not achievable by prompting the author mid-session.
(c) Read/shell/search, no edit; strong model; findings-only output with
confidence gate.
(d) 10 diffs with seeded defects: precision/recall vs base self-review.
Kill if recall delta <10 points.

**3. task-runner** (new; mirrors Copilot `task`)
(a) Runs tests, builds, linters; reports verdicts.
(b) A 400-line test log in the main window is pure rent; a prompt saying
"be brief" does not stop the tool output from landing in context.
(c) Shell-led surface, cheap model; output contract: summary on success,
full output on failure.
(d) 5 failing-suite runs: main-context tokens + failure-cause accuracy
vs inline runs. Kill if context saving <30%.

**4. build-error-resolver** (ECC port, keep)
(a) Broken build / type errors → green, minimal diff.
(b) Its contract is behavioral: minimal-diff-only, no architecture edits,
loop until green. Base agent "fixing the build" reliably improves things
that weren't broken.
(c) Same tools as base — differentiation is the output contract +
trigger (build failure), the weakest axis set here; ranked accordingly.
(d) 10 seeded TS build breaks: turns-to-green and diff size vs base.
Kill if base matches on both.

**5. security-reviewer** (ECC port, keep)
(a) Vulnerability pass on changed code.
(b) A dedicated checklist (OWASP classes, secrets, SSRF) with an
exploitability bar produces different findings than general review;
both Copilot and ECC keep it separate from code review — observed
convergence, two independent sources.
(c) Read/shell/search, no edit; checklist prompt; high-confidence gate.
(d) 8 seeded vulnerabilities: detection rate vs code-reviewer on the
same diffs. Merge into code-reviewer if it detects ≥90% of these.

**6. evaluator** (data-scientist, reborn)
(a) Designs and runs measurements; issues verdicts; grades other agents'
work, including every other entry on this list.
(b) Separation of duties: the builder must not grade the build. Also the
only roster member whose output is a verdict with a pre-registered
threshold — a stance the base agent abandons under conversational
pressure.
(c) Read + shell, **no edit**; strong model; protocol prompt
(pre-register, baseline, effect size, confound hunt).
(d) 3 rigged evals (leaky split, missing baseline, cherry-picked sample):
confound-catch rate vs base asked to "validate this." Kill if base
catches ≥2 of 3.

**Provisional (ship, on probation):**
- **planner** — Copilot-side gap-filler only. (d) 5 feature plans on
  Copilot CLI, blind-scored vs base-agent plans; kill on no delta.
  On Claude it duplicates the Plan built-in until proven otherwise.
- **code-explorer** — (d) head-to-head vs each vendor's built-in explore
  on 5 tracing tasks ("how does X flow through this repo"); kill ours
  per-tool wherever the built-in ties.

**Demoted to skills (knowledge, zero axes):** backend → backend-patterns
skill; ux-ui → ux-ui skill (agent form conditional on a Playwright
verify loop); tdd-guide → already covered by tdd-workflow skill.

**Dropped:** doc-updater (redundant with wiki-lint/session-harden);
refactor-cleaner as always-on (episodic batch job — invoke as a skill
or not at all).

Net V2 default: **6 agents** (explorer, code-reviewer, task-runner,
build-error-resolver, security-reviewer, evaluator) + 2 provisional —
vs W2's 7, with backend/tdd-guide/doc-updater out and explorer/
task-runner/evaluator in. Description rent of the 6: est. ~300 tokens —
less than the current 12-agent canonical set, with every slot
differentiated on ≥1 axis and carrying a kill test.

## 5. What would change this

The A/B program in §4(d) is runnable under the project's existing eval
harness pattern (pre-registered thresholds, `evals/results/` records,
ledger updates). Expected kills: 1–2 of the 8. That is the point of
deriving the roster this way — every entry is a hypothesis with a test
attached, including the three Samuel named. If explorer and task-runner
fail their context deltas, the honest roster is four agents and two
vendor built-ins, and the demo should say exactly that.
