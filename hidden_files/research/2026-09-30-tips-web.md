## Claude Code

### C1. Use `--bare` as a harness-free control — and call it by its real name
- **What:** `--bare` is the documented way to run Claude Code with the harness switched off; it is
  the correct baseline arm for measuring model-only behavior, not a normal coding mode.
- **Mechanism:** Per the official CLI reference, `--bare` is a "minimal mode: skip auto-discovery
  of hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory, and
  CLAUDE.md so scripted calls start faster." It sets `CLAUDE_CODE_SIMPLE`, leaves Bash / file-read /
  file-edit tools, and still loads skills from a directory passed with `--add-dir`. Authentication
  is strictly `ANTHROPIC_API_KEY` or an `apiKeyHelper` via `--settings` — OAuth and keychain are
  never read. Anthropic's headless docs call it "the recommended mode for scripted and SDK calls"
  and say it "will become the default for `-p` in a future release." Context you still want must be
  passed explicitly (`--append-system-prompt-file`, `--settings`, `--mcp-config`, `--agents`).
- **Source:** https://code.claude.com/docs/en/cli-reference (official, crawled 2026-09-30); changelog
  origin v2.1.81 per https://github.com/anthropics/claude-code/issues/36852 (2026-03-20, resolved).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips / correction:** Our notes previously called this "lean mode." That term is not
  in Anthropic's docs. Drop it: the name is **Claude Code `--bare` mode**. Do not present `--bare`
  as a productivity tip — it intentionally removes the very harness (hooks, instructions, MCP)
  that our setup is built around. Its value here is as a control arm in A/B measurements.

### C2. Capture literal Messages API bodies with file-mode OTel
- **What:** You can record the exact request/response JSON Claude Code sends, instead of guessing
  what the harness put in the prompt.
- **Mechanism:** `CLAUDE_CODE_ENABLE_TELEMETRY=1` plus `OTEL_LOG_RAW_API_BODIES=file:<dir>` writes
  untruncated `*.request.json` / `*.response.json` files plus body references. Inline mode (`=1`)
  truncates at 60 KB; file mode does not. Extended-thinking content stays redacted even in raw
  bodies, so absence of thinking text in the capture is expected, not a capture failure.
- **Source:** Anthropic monitoring-usage reference, mirrored at
  https://github.com/najeebullah3124/awesome-claude-universe/blob/HEAD/claude-code-docs/docs/monitoring-usage.md
  (retrieved 2026-09-30); practical TUI workflow:
  https://github.com/kaihendry/claude-otel-gui/blob/HEAD/README.md (retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips:** New; nothing in `tips-claude.md` covers raw-body capture. Parent already
  live-proved file mode locally on 2026-09-30 (~01:24 ET: 1,866 input tokens, 5,417-byte request
  JSON, 1,745-byte response JSON, `index.jsonl` present) — locally **PROVEN**, and the strongest
  available evidence about what Claude's harness actually sends.

### C3. Route failures to `PostToolUseFailure`, not `PostToolUse`
- **What:** Success and failure are separate hook events; a failure counter hung off `PostToolUse`
  silently records nothing.
- **Mechanism:** `PostToolUse` fires only after successful tool execution; `PostToolUseFailure` is
  the dedicated failure event. Mapping: `PreToolUse` = prevention / argument modification,
  `PostToolUse` = react to successes, `PostToolUseFailure` = failure accounting, `SessionStart` =
  context priming, `Stop` = completion gate, `PreCompact` = persist state before compression.
  General rule: hooks are deterministic enforcement; instructions are advisory. Anything that must
  not be left to model discretion belongs in a hook.
- **Source:** https://github.com/paulo-yamagishi/claude-code-setup/blob/HEAD/core/hooks-events-reference.md
  and https://github.com/robman/claude-code-thyself/blob/HEAD/docs/sdk-reference.md
  (both retrieved 2026-09-30); synthesis in
  https://github.com/moabualruz/fulcrum/blob/HEAD/docs/hooks.original.md (retrieved 2026-09-30).
- **Tag:** `COMMUNITY-REPORT` (mechanism confirmed locally — see below)
- **vs. existing tips:** Directly explains the E4 adapter bug already in our ledger, where failures
  were initially hooked to the wrong event. Locally **PROVEN** in E4 on 2026-09-30: after remapping
  to `PostToolUseFailure`, Claude captured 5/5 induced failures. Keep the community tag on the
  write-up because event semantics were cited from community references, but the behavior itself is
  locally verified.

### C4. Keep noisy exploration inside isolated subagent contexts
- **What:** Big file reads and search traces should live and die in a worker's context; the parent
  should receive a compressed result.
- **Mechanism:** A subagent's exploration output never enters the parent context — only its final
  message does. Anthropic's large-codebase guidance frames this as "the harness matters as much as
  the model." Practitioner rule that makes it work: one job per subagent, an explicit "done means,"
  declared inputs, a fixed output format, and a stop condition.
- **Source:** Official article dated 2026-05-14, summarized at
  https://github.com/gsarig/ai-playbooks/blob/HEAD/resources/reviews/how-claude-code-works-in-large-codebases.md;
  practitioner rules dated 2026-09-25:
  https://github.com/bendusz/deliver/blob/HEAD/docs/research/2026-09-25-claude-subagent-definition-practices.md
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS` (principle) / `COMMUNITY-REPORT` (task-spec rule)
- **vs. existing tips:** Extends, doesn't duplicate. Note: community claims about exact subagent
  concurrency limits and `context: fork` were **not** confirmed in official docs and are excluded.

### C5. Delegate mechanical work to cheaper models by judgment
- **What:** Let the frontier model decide which subtasks a cheaper model can safely do, instead of
  running everything at top tier.
- **Mechanism:** The main model spends its expensive tokens on classification, design, and review;
  mechanical implementation (boilerplate, search-and-replace, test scaffolding) is delegated to a
  lower-cost subagent model. The saving comes from the ratio of planning tokens to bulk tokens.
- **Source:** Simon Willison, dated 2026-07-03, preserved at
  https://github.com/nikhil-vytla/hatch/blob/HEAD/claude-fable-5-tips/sources/simon-willison-fables-judgement.md
- **Tag:** `COMMUNITY-REPORT`
- **vs. existing tips:** New. Do not present as documented model behavior — it is a prompting
  pattern reported by one practitioner; its effectiveness here is **UNVERIFIABLE** until measured
  on our own workloads.

### C6. Verification loops are the dominant quality lever
- **What:** Give the agent an executable way to check its own work; this beats better prose prompts.
- **Mechanism:** Tests, linters, and browser checks convert guesses into observable pass/fail
  evidence, letting the agent iterate against ground truth instead of its own confidence.
- **Source:** Anthropic best-practices material, mirrored at
  https://github.com/sullivan-street-projects/anthropic-docs-local/blob/HEAD/claude-code/best-practices.md
  (retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips:** Consistent with our existing `/doctor prompt-audit` and verification
  practice; adds the explicit claim from Anthropic that the feedback loop is the highest-leverage
  change, which justifies spending setup effort there first.

### C7. Re-review CLAUDE.md after major model changes
- **What:** Instructions written to compensate for an older model's weaknesses can actively
  constrain a newer one.
- **Mechanism:** Anthropic's large-codebase guidance recommends reviewing harness instructions
  every 3–6 months: compensatory rules ("always do X twice," verbose scaffolding) stop paying for
  themselves and start costing tokens and freedom. Delete or downgrade rules that the current
  model no longer needs.
- **Source:** Official article dated 2026-05-14, mirrored at
  https://github.com/q0821/llm-wiki/blob/HEAD/wiki/src-claude-code-in-large-codebases.md
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips:** New maintenance rule; interacts with the Opus 5.5 migration notes already
  in `tips-claude.md` — each model migration should trigger an instruction audit, not just a
  compatibility check.

### C8. Use OTel hook metrics to find bloated hooks
- **What:** Hook output is context; oversized hook output is a hidden token cost.
- **Mechanism:** Claude Code v2.1.280 (2026-09-22) added hook output size and spill-to-file counts
  to the `hook_execution_complete` telemetry event, so you can identify which hooks inject the most
  context or spill most often, then trim or summarize their output.
- **Source:** Changelog mirror:
  https://github.com/jaewilson07/vendor-docs-sync/blob/HEAD/claude-code-docs/changelog.md
  (v2.1.280, 2026-09-22).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips:** New; pairs with C2 — raw bodies show *what* the prompt contained, hook
  metrics show *which hook* put it there.

## Copilot CLI

### P1. Use the native file exporter before deploying any collector
- **What:** Copilot CLI can write full OTel traces to a local file with one environment variable —
  no collector infrastructure needed.
- **Mechanism:** `COPILOT_OTEL_FILE_EXPORTER_PATH=<file>` automatically enables OTel and selects
  the file exporter. Adding `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true` captures
  content fields: `gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.system_instructions`,
  `gen_ai.tool.definitions`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`. This is a
  structured OTel GenAI representation — **not** byte-for-byte provider wire bodies. Do not call it
  "raw API capture"; that term is only accurate for Claude's C2.
- **Source:** https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference
  (official, retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips:** New, and the direct counterpart to C2. The Claude-vs-Copilot evidence
  asymmetry (literal bodies vs. semantic trace) must be stated whenever the two are compared.

### P2. Decompose token overhead from the trace, not from vibes
- **What:** The observed ~14.5k Copilot input tokens can be attributed, span by span, instead of
  treated as a mystery constant.
- **Mechanism:** An `invoke_agent` trace contains child `chat <model>` and `execute_tool <tool>`
  spans carrying token counts and tool definitions. Compare, per run: system instructions,
  serialized tool schemas, context messages, actual model-call count, cache reads/writes. Whatever
  dominates that breakdown is the lever; everything else is noise.
- **Source:** https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference
  (official, retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`
- **vs. existing tips:** New methodology for the open "why 14.5k vs 1.9k?" question (see X1).

### P3. Keep content capture temporary; metadata-only is the safe default
- **What:** Run OTel without message content except during controlled diagnostics.
- **Mechanism:** Metadata-only telemetry still yields model, token, latency, error, and tool-call
  structure. GitHub warns content capture may expose sensitive code and prompts; enabling it
  permanently turns a debug aid into a data-leak path.
- **Source:** https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference
  (official, retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS`

### P4. Use BYOK to hold the model constant across harnesses
- **What:** Point Copilot CLI at Anthropic directly so the same model runs under both harnesses.
- **Mechanism:** `COPILOT_PROVIDER_TYPE`, base URL, API key, and model ID configure an external
  provider; Copilot then calls Anthropic with your key, so model and account stay fixed while only
  the harness changes — the cleanest available A/B design. Caveat: `/delegate` remains
  GitHub-hosted and is a different execution path, so results from it don't describe BYOK runs.
- **Source:** Official concepts surfaced via
  https://github.com/ks6088ts/template-github-copilot/blob/HEAD/docs/copilot_cli_tutorial/features.md
  (retrieved 2026-09-30); practical variables:
  https://github.com/dbroeglin/github-copilot-lab/blob/HEAD/docs/byok-and-local-models.md
  (retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS` (feature) / `COMMUNITY-REPORT` (variable recipes)
- **vs. existing tips:** New. Locally **PROVEN** 2026-09-30 (~01:07 ET) on Copilot CLI v1.0.89 with
  Claude Haiku 4.5.

### P5. `/fleet` only for independent work; inspect with `/tasks`
- **What:** Parallel subagents help only when the workstreams genuinely don't interact.
- **Mechanism:** Fleet workers run in isolated contexts, reducing parent-context pollution; `/tasks`
  exposes their state. Coupled work run in parallel produces merge-shaped problems that cost more
  than the parallelism saved. Recent CLI also added queued prompts/commands, headless `--plan` +
  autopilot, and `/rewind`.
- **Source:** GitHub release material dated 2026-08-13:
  https://github.com/steveash/hitchhikers-guide-to-ai-native-engineering/blob/HEAD/source-notes/docs-github-copilot-weekly-releases-aug10-2026.md;
  operational map: https://github.com/devarfeen/agent-skills-kit/blob/HEAD/skills/agents-md/references/copilot-tools.md
  (retrieved 2026-09-30).
- **Tag:** `COMMUNITY-REPORT`
- **vs. existing tips:** New; complements the rubber-duck critic already documented. Same one-job /
  done-means / stop-condition discipline as C4 applies.

### P6. Custom orchestrators need the `agent` tool, or they can't delegate
- **What:** An agent profile that describes delegation but lacks the agent/task capability will
  talk about subagents and never spawn one.
- **Mechanism:** Profiles live in `.github/agents/*.agent.md` with an explicit tool allowlist.
  Delegation requires the agent tool in that list; keep tools narrow and roles explicit. Related
  recent change: since v1.0.86 (2026-09-17), custom agents opt into repository instruction files
  (`AGENTS.md`, `copilot-instructions.md`, `CLAUDE.md`) only by setting
  `include-custom-instructions: true` in frontmatter — an opt-in that's easy to miss and silently
  changes what a custom agent "knows."
- **Source:** https://github.com/ms-mfg-community/day-in-the-life-copilot-lab/blob/HEAD/workshop/slides/30-module-3.md
  (retrieved 2026-09-30);
  https://github.com/github/copilot-cli/blob/HEAD/changelog.md (v1.0.86, 2026-09-17).
- **Tag:** `COMMUNITY-REPORT` (orchestrator mechanics) / `VERIFIED-BY-OFFICIAL-DOCS` (frontmatter opt-in)

### P7. Copilot hooks: documented and changelog-maintained, but REFUTED on our installed build
- **What:** GitHub documents Copilot CLI hooks and actively fixes them — yet our installed v1.0.89
  executed none in controlled tests. Both facts belong in the record.
- **Mechanism (documented):** Hooks live in `.github/hooks/*.json` (or user-level `~/.copilot/hooks/`);
  `preToolUse` receives `toolName` and `toolArgs` (a JSON *string* that must be parsed) and can deny
  execution; GitHub's tutorial builds a prompt audit log at `.github/hooks/logs/audit.jsonl` on this
  mechanism. The changelog shows live maintenance: v1.0.88 (2026-09-22) fixed hook commands without
  explicit `cwd` to run from project root again, and made session/subagent start hooks combine
  additional-context contributions within the hook-output limit.
- **Source:** https://docs.github.com/en/copilot/tutorials/copilot-cli-hooks (official, crawled
  2026-09-30); https://github.com/github/copilot-cli/blob/HEAD/changelog.md (v1.0.88, 2026-09-22).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS` (documented behavior) — **contradicted by local measurement**
- **vs. existing tips / CONTRADICTION:** Community sources routinely claim Copilot CLI repository
  hooks "just work." On our installed v1.0.89, discriminating tests executed 0/5 repository hooks
  with no marker produced. Local verdict: **REFUTED** for this build. Do not claim hook parity with
  Claude Code (C3). Do not resolve the contradiction by deferring to the docs — record it, and
  retest on the next installed version before relying on any Copilot hook for enforcement.

### P8. Treat recent context optimizations as hypotheses until traced
- **What:** GitHub has shipped smarter prompt caching, deferred tool loading, and purpose-built
  agentic tools that reduce token usage — mainly documented around VS Code.
- **Mechanism:** Deferred tool loading keeps unused tool schemas out of the request until needed,
  shrinking the always-on prefix; prompt caching then discounts the stable remainder. Whether these
  fully apply to standalone CLI v1.0.89 is not established by the release summaries.
- **Source:** https://github.com/auxchan/auxsays.github.io/blob/HEAD/auxsays/updates/generated/2026-05-06-github-copilot-github-copilot-in-visual-studio-code-april-releases.md
  (release summary, April/May 2026).
- **Tag:** `COMMUNITY-REPORT`
- **vs. existing tips:** Do not cite as CLI behavior. Verify with a P1/P2 trace before repeating.

### P9. Copilot CLI 1.0.89 now reads `.claude/rules` — Claude's path-scoped rules crossed over
- **What:** A Claude Code convention is now a Copilot CLI input.
- **Mechanism:** The v1.0.89 changelog (2026-09-28) adds "support for Claude Code rule files in
  .claude/rules as custom instructions." The same release adds claude-opus-5.5 to the model picker.
  Skills discovery likewise spans `.github/skills/`, `.claude/skills/`, and `.agents/skills/`, so one
  `SKILL.md` in `.claude/skills` serves both tools.
- **Source:** https://github.com/github/copilot-cli/blob/HEAD/changelog.md (v1.0.89, 2026-09-28);
  discovery map: https://github.com/ejtx16/claude-code-copilot-cli-agentic-coding-skill/blob/HEAD/skills/agent-scaffold/references/copilot-cli-formats.md
  ("verified 2026-09 against docs.github.com").
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS` (`.claude/rules` support, per official changelog)
- **vs. existing tips / CONTRADICTION:** `tips-claude.md` treats path-scoped `.claude/rules/` as a
  Claude-only mechanism. As of 2026-09-28 that is no longer true for rules *files* — but note the
  semantic gap: Claude applies rules by path scope; Copilot ingests them "as custom instructions."
  Same files, different loading semantics. Verify scope behavior before assuming parity.

### P10. Instruction precedence: GitHub's own docs disagree — design for no-precedence
- **What:** There is no single trustworthy precedence order for Copilot instruction files; the
  practical rule is to make conflicts impossible.
- **Mechanism:** GitHub's general response-customization doc publishes an order — personal >
  path-specific (`.github/instructions/**/*.instructions.md`) > `.github/copilot-instructions.md` >
  `AGENTS.md` > organization — which makes `AGENTS.md` the *fallback*, surprising for teams treating
  it as the single source of truth. Crucially, "all sets of relevant instructions are provided to
  Copilot": precedence only hints the model which line to follow; the loser still costs tokens.
  CLI-specific material contradicts the general doc: GitHub's CLI best-practices page says
  repository instructions take precedence over global ones, and community-verified CLI references
  report files are "combined; duplicates removed; no precedence order." One practitioner source
  even claims personal instructions outrank repository ones in the CLI.
- **Source:** https://docs.github.com/en/copilot/concepts/prompting/response-customization
  (official, crawled 2026-09-30, via analysis at
  https://github.com/marius-bughiu/start-debugging/blob/HEAD/site/src/content/blog/2026/09/copilot-memory-vs-repository-custom-instructions-vs-agents-md.md,
  2026-09); CLI best practices mirrored at
  https://github.com/autovixai/docs/blob/HEAD/content/copilot/how-tos/copilot-cli/cli-best-practices.md
  (retrieved 2026-09-30).
- **Tag:** `VERIFIED-BY-OFFICIAL-DOCS` that the general order exists; **UNVERIFIABLE/conflicting**
  for the CLI specifically.
- **vs. existing tips:** Refines (does not overturn) our "no documented general precedence" line:
  an order *is* documented for Copilot generally, but CLI behavior per official+community sources
  is combine-and-dedupe. Both tools read overlapping files, so keep one canonical text (see X2) and
  never rely on precedence to resolve a contradiction — the model resolves it, unpredictably.

### P11. Token-cost mechanics: every tool schema is paid context, and the prefix is the bill
- **What:** Two numbers govern Copilot CLI cost: tool-schema tokens in every request, and the
  cached-prefix discount on whatever stays stable.
- **Mechanism:** Each enabled MCP tool contributes roughly 100–500 tokens (name, description,
  parameter schema) to *every* request; one measured production setup had a single plugin injecting
  ~27K tokens per message, invisible until `/context` was run. Conversely, prompt caching serves a
  stable prefix at ~10% of input price (5-minute TTL; first write costs ~25% extra), so the large
  always-on block is cheap *only while it doesn't change*. Toggling MCP servers, tools, or the
  custom agent mid-session rewrites the prefix, forfeits the discount, and strands old context
  under the new tool set — choose the tool/agent set up front, or start a fresh session.
- **Source:** https://github.com/olivomarco/github-copilot-token-optimization/blob/HEAD/docs/08-mcp-tool-costs.md
  (retrieved 2026-09-30; cites Dina Berry's 2026-05-06 measurement);
  https://github.com/copilot-academy/copilot-academy.github.io/blob/HEAD/labs/context-engineering-lab.md
  (GitHub Copilot Academy, retrieved 2026-09-30).
- **Tag:** `COMMUNITY-REPORT`
- **vs. existing tips:** New, and it reframes P2: the 14.5k-token input is mostly a *cached* cost,
  so raw token comparisons against Claude overstate the dollar gap unless cache reads are counted.

### P12. Deduplicate ambient instructions; keep volatile state out of the prefix
- **What:** Copilot CLI loads both `AGENTS.md` and `.github/copilot-instructions.md` — repeating the
  contract in both pays for the duplication on every turn.
- **Mechanism:** Keep the full contract in `AGENTS.md`; make the Copilot file a thin pointer.
  Current status belongs in `todo.md` / handoff files loaded only when relevant, not in always-on
  instructions, because exact-prefix caching breaks whenever the prefix is edited.
- **Source:** https://github.com/irtechie/working-skill-repo/blob/HEAD/docs/context/research/2026-07-09-cross-runtime-token-efficiency.md
  (dated 2026-07-09).
- **Tag:** `COMMUNITY-REPORT`
- **vs. existing tips:** Extends X2 with the caching rationale; consistent with our `CLAUDE.md` →
  `@AGENTS.md` bridge pattern on the Claude side.

## Cross-tool / workflow

### X1. Run one model through both harnesses; compare normalized events
- **What:** The "why 14.5k vs 1.9k input tokens?" question is answerable, with different evidence
  on each side.
- **Mechanism:** Claude gives literal request/response JSON (C2); Copilot gives an OTel GenAI
  representation (P1/P2). Normalize both into the same event schema — system instructions,
  messages, tool schemas, tool calls/results, token accounting including cache reads — then diff.
  Combined with BYOK (P4) the model and account are identical, so any remaining delta is harness.
- **Source:** Synthesis of C2 + P1/P2/P4 (sources above).
- **Caveat:** The comparison is asymmetric by construction: Claude's evidence is byte-level,
  Copilot's is semantic. State that asymmetry wherever the numbers are quoted.

### X2. Shared `AGENTS.md`, native adapters for everything else
- **What:** One behavioral contract can serve both tools; nothing else about the harnesses is
  shared.
- **Mechanism:** `AGENTS.md` standardizes instructions only. Hooks, agent definitions, plugin
  formats, permissions, lifecycle events, and telemetry remain tool-native configuration (and, per
  P7/P9, even shared *files* load with different semantics). Our existing `CLAUDE.md` → `@AGENTS.md`
  bridge is the right shape; P12 is its Copilot-side mirror.
- **Source:** Synthesis of P9/P10/P12 + existing project practice.

### X3. Keep session continuity in portable Markdown, not provider memory
- **What:** Cross-tool memory works when it's files neither vendor owns.
- **Mechanism:** A plain-text session/wiki record written by one tool is readable by the other;
  provider-side memory features have no documented precedence against instruction files (P10's
  "hole") and don't transfer. Locally **PROVEN** in E2 on 2026-09-30: Claude answered 5/5 questions
  from a Copilot-created session record, while the no-wiki baseline correctly answered "not
  recorded" 5/5.
- **Source:** Local E2 result + P10 sources.

### X4. Telemetry is data, not prompt context
- **What:** Raw traces and failure events belong in files; only summaries go back to the agent.
- **Mechanism:** Feeding raw OTel/bodies into the conversation re-inflates the context the
  telemetry was meant to diagnose. Write traces to sidecars (C2, P1), analyze offline, and inject
  only the specific evidence a decision needs.
- **Source:** Synthesis of C2/C8 + P1–P3.

### X5. Maintain a claims ledger; preregister eval thresholds
- **What:** Provider docs, observed runtime behavior, community reports, and inference are four
  different kinds of evidence — keep them in separate columns.
- **Mechanism:** Every capability claim carries PROVEN / REFUTED / UNVERIFIABLE plus its source
  class (this document's tags). Contradictions (P7, P10) are preserved as first-class entries
  instead of being averaged away, and eval pass bars are set before runs, not fitted after.
- **Source:** Project practice (`AGENTS.md`, `docs/claims-ledger.md`); validated by P7, where the
  documented behavior and the installed build flatly disagree.

   1.0.89 (2026-09-28) ingests them as custom instructions, with different loading semantics.
4. Any wording calling Copilot OTel output "raw API bodies" is wrong (P1). Only Claude's file-mode

## Highest-value findings

Of everything above, five findings carry the presentation and the setup work. First, the telemetry
asymmetry: Claude Code's file-mode OTel (`OTEL_LOG_RAW_API_BODIES=file:<dir>`, C2) yields literal
Messages API bodies while Copilot CLI's file exporter (P1) yields a structured GenAI representation,
so cross-harness comparisons must normalize events rather than pretend both sides offer "raw
capture." Second, Copilot's ~14.5k input tokens are decomposable from its own `invoke_agent` trace
(P2) and, per P11, are mostly cache-discounted prefix — the number is explainable and cheaper than
it looks, but only trace data, not token totals, can prove it. Third, BYOK (P4) makes a true
same-model, same-account harness A/B possible, which combined with `--bare` (C1) gives both a
harness-free control and a harness-swap treatment — the cleanest experimental design available.
Fourth, deterministic enforcement belongs in native hooks with separate success/failure events
(C3), but installed-version validation is non-negotiable: Copilot's hooks are officially documented
yet executed 0/5 on our v1.0.89 build (P7), a contradiction that would silently sink any parity
claim. Fifth, the durable cross-tool assets are boring ones — a shared `AGENTS.md` with native
adapters (X2), portable session notes (X3), and now `.claude/rules` files that both tools read
(P9) — because they survive exactly the kind of vendor drift this research kept surfacing.
