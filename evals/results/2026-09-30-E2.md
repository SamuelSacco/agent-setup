# E2 — Cross-tool session continuity (2026-09-30)

Claim: work started in one tool can be continued by the other from the shared
session log + wiki, with no copy-paste from the user.
Threshold: tool B, cold, answers 4/5 probes whose answers exist only in
tool A's session log/notes. Anything invented = failure.

## Method

- Tool A (Copilot CLI, GitHub-hosted): real task in a scratch copy —
  added `slugify(text)` to `demo/service.py` + 5 stdlib unittest cases,
  opened and hardened a session record via the session-harden flow.
  Cost: 0.84 AI Credits.
- Tool B (Claude Code, cold, Haiku via API-key helper): 5 probes, read-only.
  Transcripts: `2026-09-30-E2-claude-transcript.json` (main),
  `2026-09-30-E2-baseline-transcript.json` (control).

## Answers (main run, 5/5 correct)

1. Change + why — correct: slugify helper + 5 tests, intent quoted from the
   session record's Intent section.
2. Separator decision — correct: hyphen; underscore considered and rejected
   because it violates the explicit hyphen format.
3. Failure — correct: first wiki-log read used an invalid negative
   `view_range`; recovered by reading with `tail`. No test failures.
4. Which wiki note records the decision — correct answer is "none", and
   Claude said exactly that, citing the record's own statement that no
   durable note was needed. No fabrication.
5. Remains open — correct: nothing, per the record's Outcome section.

Cost: $0.0265, 4 turns.

## Baseline control (wiki/ removed)

Same 5 probes: all five answered "not recorded". Claude could see the code
diff and the hyphen in the regex, and still refused to invent the rejected
alternative, the failure, or the open-items list. One aborted run ($0.055,
max-turns) preceded the clean baseline; recorded here for honesty.

## Verdict

PASS — 5/5, control clean. The shared session record is the continuity
mechanism; the harness swap did not lose the thread.
