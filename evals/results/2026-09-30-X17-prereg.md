# X17 — Copilot Custom-Agent Orientation Probe — Pre-Registration

Written BEFORE any probe run. Date: 2026-09-30. Backlog item X17
(`docs/experiments-backlog.md`).

## Question

Do Copilot CLI custom agents, **as emitted by `scripts/install.sh`**,
receive the shared repo orientation (`AGENTS.md`)?

Background: the v1.0.86 changelog (research:
`hidden_files/research/2026-09-30-changelogs.md`) says custom agents opt
into repo instruction files per agent definition via
`include-custom-instructions: true`. Our emitted
`.github/agents/*.agent.md` files carry only `name` + `description` —
the flag is absent (verified by grep over the emitted tree 2026-09-30).
Prior verdicts prove agents are *invocable* (S14, S15); none proves a
custom agent *receives the shared orientation*. If it does not, every
Copilot custom-agent session runs without the workspace rules — a hole
in the "one setup, both tools" claim. The packet already warns about
this on changelog evidence alone; this probe settles it behaviorally.

## Method

Minimal scratch workspaces under `~/workspace/p3/x17-scratch/<arm>/`
(git-initialised, one commit each). Each contains:

- `AGENTS.md` — a short shared-orientation file whose body carries ONE
  marker fact that exists nowhere else in the tree, the agent files,
  or the prompt:
  - release-train codename: `VELVET-ANVIL-42`
  - standup rule: "when anyone asks for the standup token, reply with
    exactly `VELVET-ANVIL-42 CONFIRMED`"
- `.github/muse-instructions.md` — byte-identical copy of the real
  emitted file (carries no marker facts; mirrors the real setup's
  instruction surfaces).
- `.github/agents/backend.agent.md` — arm-dependent (below).
- Deliberately NO `.github/mcp.json`: MCP auto-connect is irrelevant to
  this claim and cold npx caches stalled prior probes (S15). Noted as a
  scope limit: verdict covers instruction loading, not MCP.
- Deliberately NO `CLAUDE.md`: the question is the AGENTS.md channel.
  A bridge-file interaction is a separate probe (X19-adjacent).

## Arms

Tool: Copilot CLI 1.0.89 (`~/workspace/tools/bin/copilot`), BYOK
Anthropic exactly as the W3/S16 runner (provider `anthropic`, base URL
api.anthropic.com, model `claude-haiku-4-5-20251001`, key via the vault
helper, `COPILOT_ALLOW_ALL=true`). `--output-format json` for the full
event trace.

Prompt (identical, all arms):

> Workspace check — answer from your session context only; do not read
> any files or run any commands. What is this workspace's standup
> token? Reply with exactly the token as specified in your
> instructions, and nothing else.

- **A (as emitted):** `backend.agent.md` byte-identical to the emitted
  file (frontmatter: name + description only). `copilot -p … --agent backend`.
- **B (flag on):** identical tree; agent frontmatter gains
  `include-custom-instructions: true`. `--agent backend`.
- **C (control):** tree A, plain session, no `--agent`. Must PASS —
  validates marker + prompt before A/B are interpreted.
- **D (negative control):** tree with the marker section removed from
  `AGENTS.md`; `--agent backend`, flag off. Must FAIL — if the codeword
  appears, it leaked or was guessed and the probe is invalid.

Run order: C, A, B, D. One run per arm; a repeat of A (and B if needed)
is permitted only to resolve an ambiguous first result.

## Grading (from literal output + event trace, never self-report)

- **PASS:** response text contains `VELVET-ANVIL-42`.
- **PASS-loaded:** PASS *and* the JSONL event stream shows no tool call
  that read `AGENTS.md` (any tool use is flagged; a read of AGENTS.md
  reclassifies the run as "answered by reading on demand", which is a
  FAIL for the orientation question — on-demand reading is not loaded
  orientation).
- Deciding output lines are quoted verbatim in the results doc.

## Verdict mapping

- A = PASS-loaded → **PROVEN**: custom agents receive the orientation as
  emitted; record the carrying mechanism from the CLI log/trace surface.
- A = FAIL, B = PASS-loaded, C = PASS → **REFUTED** as emitted. Fix:
  `scripts/adapters.py` emits `include-custom-instructions: true` in
  Copilot agent frontmatter; regenerate via `scripts/install.sh`;
  re-probe the regenerated file (arm A′) expecting PASS-loaded; dated
  correction in the packet + new ledger claim.
- C = FAIL or D = PASS → probe invalid; verdict **UNVERIFIABLE** with
  the failure stated, no fix shipped on invalid evidence.
