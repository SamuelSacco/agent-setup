# Q17 — ux-ui tools_hint MCP grant fix — Results

Date: 2026-10-01. Branch `fix/ux-ui-tools-hint` off master `1f6261b`.
Fixes the defect recorded by X4 (branch `lab/x4-ux-ui-loop`,
`evals/results/2026-10-01-X4-ux-ui-loop.md`, ledger S29 there):
the shipped ux-ui agent's canonical `tools_hint: [read, edit, shell]`
emitted a Claude allowlist of `[Read, Write, Edit, Bash]` — no
`mcp__playwright__*` entries — so the agent could not run the
Playwright browser-verification loop its own canonical working
rules require ("Verify rendered output where a browser/preview is
available"). X4 arm B made zero Playwright calls; arm A (base,
30 tools) closed the loop.

## The change

1. `canonical/agents/ux-ui.md` — `tools_hint` is now
   `[read, edit, shell, mcp:playwright]`.
2. `scripts/adapters.py` — `translate_tools_hint` accepts a
   named-server MCP grant token, `mcp:<server>` (server name
   validated against `[a-z0-9][a-z0-9-]*`; `<server>` is a
   `canonical/mcp/<server>.json` name). Rendering is per tool:
   - Claude: `mcp__<server>__*` (wildcard allowlist entry for that
     server's tools — the form this repo's P2 install-matrix probe
     used for MCP allowlist entries).
   - Copilot: `<server>/*` (the shared `.agent.md` MCP vocabulary).
     Copilot-side runtime *enforcement* of the emitted MCP names is
     UNVERIFIABLE from this sandbox (same standing caveat as S21's
     category names); no Copilot probe was run for this fix.
   A malformed `mcp:` token aborts the install with a named error,
   same as an unknown category — no silently dropped restriction.
3. Emitted files (tracked adapter output, regenerated by install):
   `.claude/agents/ux-ui.md` and `.github/agents/ux-ui.agent.md`.

No other agent's emitted allowlist changed (install output for the
other 11 agents is byte-identical categories as before).
