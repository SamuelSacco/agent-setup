## Claude Code — PASS (5/5), after an adapter fix

First run with the original adapter: **0/5 events**. Diagnosis: the adapter
mapped canonical `tool_failure` to Claude's `PostToolUse`, which fires only
on success — the only events recorded were 4 successful `Read` calls,
mislabeled `tool_failure`. Claude exposes failures on a separate event,
`PostToolUseFailure`.

Adapter fixed (`scripts/adapters.py`: `tool_failure` → `PostToolUseFailure`)
and retested: **5/5 parseable events**, each with UTC timestamp, kind
`tool_failure`, tool name, and the real error text
("command not found: python", "Expecting property name enclosed in double
quotes…"). Transcript: `2026-09-30-E4-claude-transcript.json`. Cost $0.0257.

This is the adapter layer earning its keep: the canonical concept was right,
the native mapping was wrong, and only a live failure test could show it.
