## Claim

Ledger C3: "Opus 5.5 makes older prompts behave worse."

## Models (to be verified after this preregistration)

Target: `claude-opus-5-5` (newer) vs the newest prior Opus the API actually offers (older).
Only model IDs returned by `GET /v1/models` will be used; no ID is guessed.
If two Opus generations are unavailable, fall back to two generations of another family and
record the substitution as a dated amendment in the results file. If no generational pair
exists, the verdict is UNVERIFIABLE for availability. Exact IDs used are recorded in results.
One attempt per cell, temperature 0 if the API accepts it, max_tokens 64.

## Design

Cells: 2 generations x 2 prompt styles x 5 tasks = 20 calls. Source of truth for prompts
(byte-identical to the blocks below): `evals/x21/prompts.json`. The runner reads that file only.
Legacy scaffolding is planted as text inside the prompt (XML wrapping, filler, few-shot block,
and a textual assistant-prefill-style opening line), not as an API prefill message, so the
same call shape is valid on both generations.

## Grading method

Deterministic, disk-only. Every raw API response is saved under `evals/x21/raw/`.
Score per cell: 1 iff the response text, stripped of leading/trailing whitespace, is an
exact case-sensitive match to the expected string above; otherwise 0. Grading is performed
by `evals/x21/grade.py` run over the saved raw outputs; no self-report, no LLM judge.
API errors count as 0 for that cell and are recorded verbatim. Totals are per style per
generation (max 5 each).

## Decision rule (verbatim)

C3 degradation is PROVEN iff legacy-style total score on the newer generation is worse than on the older generation by >=2 task-points AND modern-style score on the newer generation is not worse than on the older. REFUTED iff legacy score on the newer generation >= legacy score on the older generation. Otherwise UNVERIFIABLE.

## Spend metering

Usage (input/output tokens) is read from each API response and saved with the raw output.
Cost is computed from those token counts at the per-model rates stated in the results file;
cumulative spend is tracked during the run and no call starts if it would exceed $3.50.
